# 프로젝트 회고

시스템 엔지니어 관점에서 서비스를 올리는 것부터 배포·확장·알림·복구까지 연결해서 실습해본 프로젝트다.

처음에는 Terraform 리소스를 더 추가하면 완성도가 높아지는 줄 알았다. 진행하면서 느낀 건, 필요한 구성을 정하고 실제로 동작하는지 확인하는 게 더 중요하다는 점이었다.

## 배운 점

- 파드의 Running 상태만으로 끝내지 않고 Ready 상태와 실제 접속까지 확인해야 했다.
- 파드 확장과 노드 확장은 따로 봐야 했다. 자원과 배치 조건도 영향을 줬다.
- 저장소가 있으면 파드만 옮기면 되는 게 아니었다. 가용 영역과 볼륨 연결도 확인해야 했다.
- 코드 수정, 이미지 빌드, 실제 배포 완료는 각각 구분해서 확인해야 했다.
- 최종 plan에서 No changes가 나오는지 확인하며 코드와 실제 환경을 맞췄다.

## 앱은 실습에 필요한 만큼만

회원가입·로그인, 관리자 상품 등록, 이미지 업로드, 수량 선택·장바구니 주문, 운영자 주문 알림을 구성했다. 관리자 페이지에는 Grafana와 Argo CD 바로가기를 두고 일반 회원의 접근을 제한했다.

결제나 배송, 고객별 이메일까지 넓히지는 않았다. 여러 상품은 기존 API로 상품별 주문을 처리하고, 주문 메일도 기존 운영 SNS를 활용했다.

## 이번 실습의 범위

서비스 운영 흐름과 복구는 확인했지만 완전한 고가용성 시스템을 만든 것은 아니다. NAT와 RDS, 일부 운영 도구는 실습 비용과 복잡도를 고려한 구성이다.

추가로 개선한다면 기능을 더 넣는 것보다 알림 대응 절차와 복구 방법을 정리하고, 필요한 서비스의 가용성을 높이는 쪽으로 진행하고 싶다.
