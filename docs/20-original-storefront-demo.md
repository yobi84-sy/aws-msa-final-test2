# 초기 웹 디자인을 기준으로 한 배포 비교

V1 디자인은 사용자가 제공한 `msa_sy.zip`의 Soldesk Mall 화면을 기준으로 한다.
별도로 만든 간소화 메인 화면을 강사 제공 원본 화면으로 표시하지 않는다.

- 메인 페이지 구조와 `legacy-storefront.css`는 초기 자료의 레이아웃을 사용한다.
- 원본 ZIP의 일부 한글이 이미 깨져 있어, 같은 자료를 앞서 정리한 UTF-8 사본에서 정상 한글 문구를 가져왔다.
- 기존 test2 CSS 뒤에 초기 CSS를 적용해 초기 화면을 재현하면서 추가된 장바구니·관리자 화면의 스타일을 보존한다.
- 초기 HTML의 상품등록 메뉴는 현재 관리자 권한 정책에 맞춰 `data-admin-only`로 연결한다.
- 로그인·상품·주문 API, DB 스키마, 인증·권한 검사와 `app.js`는 현재 test2 구현을 유지한다.
- 초기 자료에 없던 관리자·장바구니·주문 화면은 test2의 추가 기능이다. 초기 앱 전체를 수정 없이 복원한 것으로 설명하지 않는다.

이 변경은 프론트엔드 이미지 배포이다. NAT·RDS·EKS 재생성을 요구하지 않는다.
초기 정상 디자인 → 변경 디자인의 상세 기능 오류 → 초기 정상 이미지로 롤백 → 수정된 변경 디자인 재배포의 실제 화면을 비교한다.

## 한시적인 V2 장애 시연

이 단계는 사용자에게 승인받은 비운영 실습 환경의 장애 시연이다. 최종 서비스 버전으로 남기지 않는다.
현대화한 test2 디자인을 복원하되 상품 카드가 전달하는 `id`와 상세 화면이 읽는 `productId`를 의도적으로 다르게 둔다.
상품 목록 API·DB·이미지는 유지되지만 정상 상품 링크를 누르면 상세 화면에 ‘상품 정보가 없습니다.’가 표시된다.
HTTP 200·Pod Ready만으로 사용자 동작 오류를 탐지할 수 없다는 점을 관찰한다.

기존 프론트엔드 검사 7개와 스크립트 검사 118개는 통과했다. 별도 준비한 ‘상품 카드 클릭 → 상세 데이터 로드’ 회귀 검사는 정상 V1에서 통과하고 이 V2에서 실패함을 로컬에서 확인했다.
현재 CI 검사를 삭제하거나 비활성화하지 않는다. 수정 재배포 단계에서 이 실제 동작 회귀 검사를 저장소의 필수 CI 테스트 범위에 추가한다.

관찰 후 `eed1154b290cdcf348f899628a02c11e4f139067`의 검증된 V1 이미지로 승인 PR을 통해 롤백한다.
DB·인프라를 롤백하지 않고 동일 상품이 다시 정상 표시되는지 확인한 뒤, 상세 파라미터를 고친 최종 test2 디자인을 재배포한다.

## V3 수정 재배포

상세 페이지가 읽는 파라미터를 상품 카드가 전달하는 `id`로 다시 일치시켰다.
`app/msa/frontend/tests/product-detail-flow.test.cjs`는 실제 카드 링크를 생성하고 그 링크의 검색 파라미터로 상세 로더를 실행해, 선택한 상품 ID의 API가 호출되고 상품명이 상세 화면에 렌더링되는지 검사한다.
이 검사는 기존 `node --test tests/*.test.cjs` 명령에 포함되므로 같은 불일치가 생기면 이미지 게시 전 CI에서 실패한다.
스크립트 캐시 URL도 V3 전용 값으로 바꿔 이전 오류 JavaScript가 브라우저 캐시로 남는 혼동을 줄였다.
