# 문제 해결 기록

구축하면서 만난 오류 중에서 원인을 이해하는 데 도움이 됐던 것들을 정리했다.

## Grafana만 503이 발생한 문제

웹사이트와 Argo CD는 정상인데 Grafana만 접속되지 않는 상황이 있었다. 노드 자원과 배치 상태, EBS가 속한 가용 영역을 함께 확인했다.

EBS는 특정 가용 영역에 속하기 때문에 다른 영역에 노드가 늘어나는 것만으로는 문제가 해결되지 않았다. 노드 그룹을 가용 영역별로 나누고, 모니터링 파드의 배치 조건과 리소스 설정을 조정했다.

이후 Grafana를 다른 노드로 이동시키는 실습을 다시 진행했고 기존 PVC를 유지한 채 복구되는 것을 확인했다. 다만 단일 파드와 단일 AZ 저장소 구성이라 무중단이나 가용 영역 전체 장애 복구를 보장하는 구성은 아니다.

## 관리자 Secret은 있는데 로그인이 안 된 문제

새 비밀번호를 설정했는데도 로그인이 실패했다. 확인해보니 새 이미지 배포가 끝나지 않아 이전 회원 파드가 요청을 처리하고 있었다.

파드별 이미지와 롤아웃 상태를 확인하고 새 버전 배포가 끝난 뒤 로그인했다. Secret 준비와 코드 배포는 따로 확인해야 한다는 점을 배웠다.

## 그 밖의 오류

| 문제 | 확인하고 해결한 내용 |
| --- | --- |
| Terraform 모듈 인자·출력 오류 | 호출부와 모듈 선언을 맞추고 파일 저장 여부 확인 |
| 명령 실행 위치·옵션 오류 | 실제 설정 폴더에서 실행하고 plan과 apply 옵션 구분 |
| PowerShell 스크립트 차단 | 현재 창 범위의 실행 정책 설정 후 실행 |
| RDS 생성 실패 | CloudTrail로 비밀번호 길이 문제를 확인하고 입력값 검증 추가 |
| CloudTrail JSON 변환 실패 | PowerShell의 키 충돌을 피하도록 Python으로 분석 |

오류가 났을 때 바로 설정을 더 추가하기보다는 이벤트와 로그를 보고 범위를 좁히는 연습이 됐다.
